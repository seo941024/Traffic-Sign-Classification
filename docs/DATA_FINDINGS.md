## 1. 다운로드 현황과 **치명적 문제**

| 세트 | 라벨 tar | 원천 tar | 라벨 수 | 원천 수 | **교집합** |
|---|---|---|---|---|---|
| **c (수도권)** | `[라벨]c_train_1280_720_daylight_1` | `[원천]c_train_1280_720_daylight_1` | 30,000 | 30,000 | **30,000** ✅ |
| d (수도권) | `[라벨]d_train_1920_1080_daylight_1` | *없음* | 15,000 | — | — ❌ |
| m (광역시 등) | `[라벨]m_train_**1280_720**_daylight_1` | `[원천]m_train_**1920_1080**_daylight_1` | 25,997 | 15,000 | **0** ❌ |

### 결론: 지금 쓸 수 있는 건 **c 세트 하나뿐**이다.

**m 세트가 안 되는 이유**: 라벨은 1280×720 세트인데 원천은 1920×1080 세트다.
해상도가 다른 **서로 다른 부분집합**이라 파일명이 하나도 겹치지 않는다.

- 라벨 파일명 범위: `i0437256` ~ `i0555071`
- 원천 파일명 범위: `i0036120` ~ `i0664417`
- 교집합: **0개**

> **해결 방법**: AI-Hub에서 `[원천]m_train_1280_720_daylight_1.tar`를 추가로 받으면 됩니다.
> (또는 `[라벨]m_train_1920_1080_daylight_1.tar`)
> 라벨과 원천은 **`X_train_해상도_daylight_N`이 완전히 같아야** 짝이 맞습니다.

**d 세트**: 라벨만 있고 원천이 없다. `[원천]d_train_1920_1080_daylight_1.tar`가 필요하다.

**다만 c 세트 30,000장만으로 1차 실험은 충분하다.** (핸드오프 12절 목표가 5,000장)

## 2. Annotation 형식

경로: `[라벨]c_....tar` → `c_train_1280_720_daylight_1/s01027933.json`
원본 이미지 1장 = JSON 1개. 플랫 구조, 하위 폴더 없음.

```json
{
  "annotation": [
    {"box":[708,177,719,188], "class":"traffic_sign", "shape":"circle", "color":"blue"},
    {"shape":"circle","color":"red","kind":"normal","box":[579,151,595,167],
     "text":"0","type":"restriction","class":"traffic_sign"},
    {"light_count":"3","box":[538,160,560,167],
     "attribute":[{"red":"off","green":"on","yellow":"off",
                   "left_arrow":"off","x_light":"off","others_arrow":"off"}],
     "type":"car","class":"traffic_light","direction":"horizontal"}
  ],
  "image": {"filename":"s01027933.jpg", "imsize":[1280,720]}
}
```

### 확인된 필드

| 필드 | 값 | 비고 |
|---|---|---|
| `box` | `[x1, y1, x2, y2]` | **픽셀 절대좌표.** 정규화 아님 |
| `image.imsize` | `[width, height]` | |
| `class` | `traffic_sign` / `traffic_light` / `traffic_information` | 객체 대분류 |
| `shape` | `circle` / `triangle` / `rectangle` | traffic_sign 전용, **결측 없음** |
| `color` | `red` / `blue` / `yellow` | traffic_sign 전용, **결측 없음** |
| `type` | `restriction` / `instruction` / `caution` / `pedestrian` | **결측 많음** |
| `kind` | `normal` / `led` | |
| `text` | `"0"` 또는 `0` | **타입 불일치** |

### `box`가 `(x1,y1,x2,y2)`인 근거

`[708,177,719,188]`을 `(x,y,w,h)`로 읽으면 `x+w = 1427`로 이미지 폭 1280을 넘는다.
따라서 `(x1,y1,x2,y2)`가 맞다.

## 3. ⚠️ 파싱 시 반드시 처리해야 할 함정

실제 데이터에서 관찰된 것들이다. **전부 에러 없이 조용히 잘못된 결과를 만든다.**

1. **좌표 순서가 뒤집힌 박스가 있다**
   `i0553098.json`: `"box":[315,308,287,335]` → `x2(287) < x1(315)`
   → `min`/`max`로 정규화하지 않으면 빈 crop이 생기는데 **예외는 안 난다.**

2. **key 순서가 객체마다 다르다** — `box` 먼저인 것도, `shape` 먼저인 것도 있다.
   순서에 의존하는 파싱 금지.

3. **`annotation`이 빈 배열인 파일이 많다** (표지판 없는 프레임)

4. **`type` 키가 아예 없는 객체가 많다** — `circle_red` 중 약 20%

5. **`traffic_light`의 `type`은 `car`/`bus`/`bicycle`** 로 표지판의 `type`과 의미가 완전히 다르다.
   → `class`로 먼저 걸러야 한다.

6. **`text` 타입 불일치** — `"0"`(문자열) vs `0`(정수)

## 4. 🔴 클래스 체계 — **핸드오프 문서 수정 필요**

**핸드오프 13절이 예시로 든 `stop`, `speed_30`, `speed_50`, `no_entry` 같은 클래스는 이 데이터에 없다.**

AI-Hub는 표지판의 **의미**가 아니라 **생김새(shape·color)와 대분류(type)**만 라벨링한다.
`text` 필드가 있지만 값이 대부분 `0`이라 속도 숫자로 쓸 수 없다.

### 객체 대분류 분포

| class | c (수도권) | m (광역시) |
|---|---|---|
| traffic_sign | 54,500 | 26,397 |
| traffic_light | 39,888 | 30,090 |
| traffic_information | 1,054 | 0 |

### 채택한 클래스: **shape × color, 6개**

`type`은 결측이 많아 제외하고, 결측이 없는 `shape`+`color`를 조합했다.

| 클래스 | c 전체 | c (≥24px) | c (≥32px) | 실제 표지판 유형 |
|---|---|---|---|---|
| `circle_red` | 27,958 | 8,153 | 4,179 | 규제표지 (속도제한·진입금지) |
| `circle_blue` | 9,710 | 2,378 | 1,158 | 지시표지 |
| `triangle_yellow` | 8,036 | 3,564 | 2,181 | 주의표지 |
| `triangle_blue` | 3,158 | 1,237 | 653 | 지시표지(삼각) |
| `rectangle_blue` | 2,904 | 872 | 427 | 안내표지 |
| `triangle_red` | 2,734 | 1,254 | 710 | 규제표지(삼각) |

→ **≥24px 기준으로 모든 클래스가 872장 이상.** 클래스당 800장씩 균형 샘플링 가능.

## 5. 🔴 bbox 크기 — **입력 해상도 재검토 필요**

`traffic_sign` bbox의 **짧은 변** 분포:

| | p5 | p10 | p25 | **p50** | p75 | p90 | p95 | p99 |
|---|---|---|---|---|---|---|---|---|
| c (수도권) | 8 | 9 | 12 | **17** | 26 | 39 | 48 | 68 |
| m (광역시) | 13 | 15 | 20 | **27** | 38 | 52 | 64 | 94 |

**절반이 17px 이하다.** 주행 영상이라 표지판이 대부분 멀리 있다.

| 임계값 | c 잔존 | m 잔존 |
|---|---|---|
| ≥16px | 31,362 (57%) | 23,694 (89%) |
| **≥24px** | **17,458 (32%)** | 16,349 (61%) |
| ≥32px | 9,308 (17%) | 10,271 (38%) |
| ≥64px | 782 (1%) | 1,343 (5%) |

### 결정: 입력 크기를 **64×64 → 32×32로 변경**

핸드오프 29.3절은 64×64를 예시로 들었지만, 원본 bbox 중앙값이 17px인데
64×64로 키우면 **없는 정보를 늘려서 만드는 것**이라 얻는 게 없다.
(GTSRB 등 공개 표지판 데이터셋도 32×32가 표준이다.)

- `MIN_BBOX_SIZE = 24` — 사람이 봐서 구분 가능한 최소선
- `IMAGE_SIZE = 32` — Flatten 시 **3,072** features

> Flatten 차원이 12,288 → 3,072로 줄지만
> **"Dense는 입력 크기에 비례해 파라미터가 늘고 Conv는 안 는다"**는
> 프로젝트의 핵심 논지는 그대로 성립한다.

## 6. 데이터 누수 방지 — 그룹 설계

**(이 절만 휴리스틱이며 검증이 필요하다)**

두 단계로 묶는다.

1. **원본 이미지 단위** (확실함)
   샘플 파일 하나에 `traffic_sign`이 6개 있었다. 한 사진에서 나온 crop들은
   배경·조명·촬영조건이 동일하므로 반드시 같은 split에 있어야 한다.
   → crop 파일명을 `{원본stem}__{순번}.jpg`로 지어 복원 가능하게 했다.

2. **주행 구간 단위** (추정)
   파일명이 `s01027933`처럼 접두사+순번이다. ID가 가까우면 연속 촬영일 가능성이 높다.
   → `config.GROUP_ID_BUCKET = 1000`으로 `s01_27`처럼 묶는다.

   ⚠️ AI-Hub가 ID를 어떻게 부여했는지 공식 문서로 확인한 것이 아니다.
   `04_build_manifest.py`의 클래스별 분포 출력을 보고 조정해라.
